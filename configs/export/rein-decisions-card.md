# Rein decisions

The synthetic training and evaluation data of [Rein](https://huggingface.co/jmc0/rein-r1-0.8b). Each record is a
conversation (context, turns with roles and `*narration*`, and sometimes the assistant's reply in progress) plus the
operator's rules, each written as a question with its own options and a label. Every record here is synthetic; the
model cards list all the data the models were trained on.

## Record format

```json
{
  "id": "full-v1-s01234-c003",
  "source": "synthetic",
  "scenario_id": "full-v1-s01234",
  "split": "test",
  "state": {
    "context": "character card, game-state flags, policy, tools",
    "conversation": [{"role": "user", "text": "...", "name": null, "tool_calls": []}],
    "draft": {"text": "reply in progress", "tool_calls": []}
  },
  "questions": {
    "rule_id": {"type": "noul | choice | score", "instructions": "...", "criteria": {"option": "description"},
                "label": "option, true/false or level", "target": {"option": 0.7, "other": 0.3}}
  },
  "meta": {"category": "...", "case_form": "...", "lang_rule": "en", "lang_conv": "pt-BR", "holdout": false}
}
```

`label` is a hard answer; `target` is a soft distribution, used when the judges or the auditor did not agree.

```python
import json
from huggingface_hub import hf_hub_download

path = hf_hub_download("jmc0/rein-decisions", "test.jsonl", repo_type="dataset")
records = [json.loads(line) for line in open(path, encoding="utf-8")]
print(records[0]["questions"])
```

Read the JSONL files directly. Each record has its own rule ids and options, so loading them as one Arrow table
(`datasets.load_dataset`) merges every rule id of every record into a single wide column.

To score a record with the model, pass `state` and `questions` (without `label`, `target`) to
`rein.decide(state, questions)` from [jmc0/rein-r1-0.8b](https://huggingface.co/jmc0/rein-r1-0.8b).

## How it was built

- **Scenarios.** Each scenario has a context and 4 to 8 rules. The categories are locked and mutable character
  attributes, breaking character, tool triggers, NPC secrets gated by game state, lore, age rating, business
  limits, mandatory phrases, compliance, routing, format and tone drift. They span companion apps, game NPCs,
  tool agents, support desks and regulated sectors.
- **Conversations.** For each target rule, cases are written in one of these forms: direct, paraphrase, slang,
  indirect, narration attack, intent spread over turns, stale trigger, early reference, distractor-heavy, other
  language, mixed PT-EN, hard negative (same words, other intent), neutral and adversarial. The decisive turn
  sits at different depths of the conversation.
- **Watcher drafts.** Replies in progress that narrate an action without the tool call, that call the tool,
  that narrate after calling, that refuse, or that are plain dialogue. Some are cut mid-sentence to simulate
  streaming.
- **Generation.** Synthetic records were generated by `QuantTrio/Qwen3.5-35B-A3B-AWQ` (Apache-2.0 base).
- **Labels.** Two framings (annotator and reviewer) label every rule. When they disagree, a thinking tiebreak
  decides, or the record keeps a soft target.
- **Audit.** Every label in every split was then audited by `Qwen/Qwen3.8-27B-FP8` (audit version `a2`).
  The auditor never sees the existing label. A fast vote screens each question; when it disagrees with the label,
  two thinking votes run, and the label changes only if both agree. A score question changes only when the gap is
  at least two levels; smaller disagreements become a soft target. Each audited record carries `meta.audit`, with
  the per-question status (`confirmed`, `corrected`, `disputed`, `abstained`), the votes and the original label.

  | Split | Records | Questions confirmed | Corrected | Disputed (soft target) |
  |---|---|---|---|---|
  | train | 16,924 | 81,040 | 2,676 | 1,333 |
  | development | 1,091 | 5,047 | 171 | 84 |
  | calibration | 1,061 | 4,993 | 195 | 97 |
  | test | 6,094 | 28,881 | 898 | 459 |

- **Language.** Conversation language is checked with lingua; mismatches are rejected.
- **Splits.** Records are split by rule, never by example. No rule text in development, calibration or test
  appears in train. One domain and one category are held out of training entirely. `stats.json` lists the records
  per split.
